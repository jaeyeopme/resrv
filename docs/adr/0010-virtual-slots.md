# ADR-0010: Virtual Slots

## Status

Accepted.

## Date

2026-05-25

## History

- `8753416 feat(timeslot): generate virtual slots`

## Context

Slots are derived from business settings, resource overrides, schedules, date, and timezone. They do
not need independent lifecycle before a customer attempts to hold one.

## Decision

Generate slots virtually.

Each slot has:

- Business ID.
- Resource ID.
- Start instant.
- End instant.
- Opaque `slotId` encoding the selected slot information.

Hold requests use `resourceId` and opaque `slotId`. Slot rows are not persisted.

## Alternatives

### Persist Slot Rows

Persisted slots are easier to lock directly but require pre-generation and invalidation when
settings or schedules change.

### Expose Raw Start/End As Booking Input

This is transparent but invites clients to construct times that were not generated by the server.

## Consequences

- Slot generation must be deterministic for the same settings/schedule/date.
- Hold creation must decode and revalidate `slotId`.
- Changing settings or schedules changes future generated slots without a migration.
