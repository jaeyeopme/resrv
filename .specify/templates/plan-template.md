## Constitution Check

*GATE: Must pass before Phase 0 research. Re-check after Phase 1 design.*

- **Boundary-first design**: The plan keeps code inside the owning bounded
  context (`platform`, `timeslot`, or `shared-kernel`) and preserves dependency
  direction: `api/runtime -> adapters -> application -> domain`.
- **Server-side authorization**: JWTs identify accounts only. Business access
  is resolved through active membership checks or reservation ownership, not
  trusted client claims.
- **Generated API contract**: API behavior changes include controllers/DTOs,
  validation, Springdoc annotations, and API integration tests. No handwritten
  endpoint catalog is introduced.
- **Reservation correctness**: Slot, hold, and reservation changes preserve
  business timezone, policy resolution, opaque slot binding, and active blocker
  semantics.
- **Quality gates**: Non-trivial changes identify the focused verification path
  and finish with `./gradlew spotlessApply`, `./gradlew rewriteDryRun`, and
  `./gradlew check` unless explicitly blocked.
